## 用户价值

作为离开电脑或同时管理多个任务的用户，我希望通过飞书正式机器人看到项目与任务的实时进度，并在需要人工决定时直接通过交互卡片批准、拒绝或选择下一步，从而不必持续守在 Codex 会话旁等待。

## 行为说明

Spec-Loop 把本地 Project、Task、Harness、Gate、Review 和 Delivery 事实投影为飞书消息卡片。普通进度尽量更新同一张项目卡片，异常和待确认事项单独提醒；用户点击卡片后，系统先验证飞书身份、租户、请求类型、Task、Round、候选 revision、有效期和单次消费状态，再调用既有 Controller 领域操作。

飞书不是第二套任务状态源。断网、机器人停用或卡片更新失败时，本地闭环状态保持不变；需要人工确认但连接器不可用时，任务进入 `needs_user` 并保留本地 CLI/对话确认入口。

## 业务规则

1. MVP 使用飞书企业自建应用机器人，不使用群聊自定义 Webhook。
2. 本地优先部署默认使用飞书官方 SDK 长连接接收事件与卡片回调，不要求暴露公网 HTTP 地址。
3. 机器人按项目配置接收人或群聊、允许确认的飞书用户和通知级别；未绑定身份只能查看允许公开的进度，不能做出决定。
4. 每个确认请求必须绑定 `project_id`、`task_id`、请求类型、Round、候选 revision、内容哈希、到期时间和允许动作。
5. 候选变化、请求过期、已消费、Task 状态变化或身份不匹配时，旧卡片操作必须 fail closed。
6. 回调只携带不透明请求 ID 和固定动作 ID；授权范围从本地请求事实读取，不能相信客户端回传的 Task、revision、scope 或 risk。
7. 同一回调可能被重复投递；系统必须按飞书事件 ID、请求 ID 和动作 ID 幂等处理，重复点击返回已有结果而不重复推进状态。
8. 允许的 MVP 确认类型为 Proposal 批准/拒绝、`needs_user` 选项、视觉 Review、当前候选正式验证授权和最终 Heavy 验收；不得通过自由文本推导授权。
9. 自动 merge、push、deploy、发布、生产修改、凭据操作和扩大权限不属于飞书 MVP 可执行动作。
10. `app_secret`、访问令牌和回调加密材料不得写入 Git、规格、Task、Ledger、日志、卡片或 Evidence；运行配置只保存凭据引用。
11. 进度消息必须合并高频事件，展示总 Task、已完成、执行中、待验证、阻塞、当前动作、最近结果和下次需要用户介入的位置，避免每个 Attempt 都发送新消息。
12. 发送限流、断线、超时和飞书服务失败必须进入 Outbox 重试与可观测状态；普通通知失败不阻断本地任务，确认投递失败必须显式暴露并提供本地回退。
13. 所有外部发送、回调接收、身份判断、授权决定、拒绝原因和重试结果必须可审计，但审计记录不保存消息正文中的敏感内容。
14. 关闭飞书连接器后，Spec-Loop 必须退回 Phase 3 本地控制方式，既有 Task 和 Evidence 不受影响。

## 验收标准

- AC-1：真实项目的总体进度卡片能准确显示任务统计、当前阶段、最近 Gate/Verifier 结果和是否需要用户介入，并以更新卡片为主而不是持续刷屏。
- AC-2：当任务需要 Proposal、`needs_user`、视觉 Review、正式验证或最终 Heavy 确认时，授权用户能在飞书卡片上完成允许的决定，并使本地 Controller 产生一致的状态与审计记录。
- AC-3：未授权用户、错误租户、过期请求、旧 revision、重复回调、篡改动作和已消费卡片都不能推进任务状态。
- AC-4：应用重启、长连接断开、发送限流或短暂网络失败后，Inbox/Outbox 可以 reconcile，且不会重复发送关键通知或重复消费确认。
- AC-5：飞书不可用时，本地闭环继续运行；需要确认的任务进入 `needs_user`，用户可通过本地入口完成同一请求。
- AC-6：凭据和令牌不会出现在 Git、Task、Evidence、日志或错误输出中，机器人权限保持发送消息、接收必要事件和识别操作用户的最小集合。
- AC-7：使用真实企业自建应用完成一次进度通知、一次拒绝或失效确认、一次有效确认和一次最终 Heavy Dogfood，独立 Verifier PASS。

## 非功能要求

- 性能：卡片回调先持久化并在飞书要求的响应窗口内确认接收；耗时 Controller 操作异步执行。
- 安全与隐私：单租户绑定、用户 allowlist、最小权限、凭据外置、请求单次消费、全链路审计。
- 兼容性：连接器默认关闭；未配置飞书时所有 Phase 1～3 能力保持可用。
- 可观测性：可查询连接状态、最近心跳、Inbox/Outbox 堆积、重试次数、最近成功发送和最近拒绝原因。
