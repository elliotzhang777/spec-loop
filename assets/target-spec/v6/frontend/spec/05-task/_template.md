## P/M/V/R 职责

- P：在 M 开始前形成完整 AC、用例、工具、断言、Evidence、风险、依赖和关键路径，并取得人工批准。
- M：只能修改实现与自测证据，不得降低或改写已批准验收契约。
- V：使用独立 invocation 按冻结 Execution Plan 验证稳定候选，包含 Playwright 功能证据但不以截图替代断言。
- R：在 V PASS 后独立复核全部 AC、Evidence hash、候选 revision、视觉审批和权限边界。

## 验证范围

- 层级：默认使用 Task 增量验证；只有整轮最终验收工单使用 Wave 全量验证。
- 所属波次：待填写，例如 W1。
- Task Gate：只覆盖本页面工单 AC、改动页面/API 契约和直接依赖，只运行对应 Playwright 路径。
- Wave Gate：所有工单合入后，由独立 Heavy 工单统一运行一次跨模块和完整浏览器链路验证。
- Gate 配置：普通工单使用 `coverage: targeted`；只有最终 Heavy 工单使用 `coverage: full`。
- 数据库：真实后端路径复用长期验证实例，不为每个页面工单创建和删除数据库容器。
- 权限边界：已批准 Task/波次范围和预算内连续实现、自测及 V/R；候选变化作废旧验证证据，不撤销范围内执行授权。最终统一确认验收、必要视觉/Heavy 审阅和外部交付动作；范围、权限、Gate 计划或预算变化先暂停受影响范围。

## Playwright 功能 Gate

- 是否需要：是。必须在控制 Task 的 `ACCEPTANCE.md.web_gates` 与 `GATES.md` 使用相同 Gate ID 和 AC 覆盖。
- 工具来源：使用目标源码仓中由 Git 跟踪锁文件约束的本地 Playwright CLI；完整 Gate Plan 和 JSON/HTML/附件 Manifest 绑定当前 revision。
- 截图策略：页面或视觉路径使用 `require_screenshots: true`；纯功能路径可显式设为 `false`，但不得替代人工视觉 Review。

## 人工视觉 Review（按需）

- 是否需要：若 AC 包含布局、样式、密度或主观效果则为“是”，并在控制 Task 的 `ACCEPTANCE.md.human_reviews` 声明 Review ID 和 AC 覆盖。
- 证据：绑定当前 Round、Git revision、完整可解码 PNG 与 SHA-256；候选或截图变化后旧批准失效。
- 边界：人工效果判断不能替代 Playwright、类型检查、构建、可访问性或其他确定性 Gate。
