# 前端 Web 规格驱动交付约定

本工程使用轻量卫星规格库。AI 和人工协作者必须以 `spec/05-task/` 中的 `WEB-TASK` 为最小执行单位，并遵循 `spec/00-conventions/development-guidelines.md`。

产品目标、业务规则、总体架构和 API 契约由后端主规格库维护；本工程只记录前端实现任务与长期工程规范。

## 开始工作前

1. 阅读 `spec/00-conventions/development-guidelines.md`。
2. 阅读工单引用的 Product、Feature、Design/API 契约及依赖任务。
3. 检查后端主规格库的 `pending-board.md` 和 `verification-board.md` 共享看板。
4. 确认页面/路由、设计来源、数据状态、响应式范围、无障碍要求和验证方式明确。
5. 若业务规则或接口契约不清晰，先回到后端主规格库补齐，不在前端工单中自行定义第二套规则。

## 规格链路

`Product / Feature / Design / API 契约 -> WEB-TASK -> 前端实现与验证`

- 上游主规格：定义为什么做、业务行为和跨端契约。
- Frontend Guidelines：定义所有 Web Task 共同遵循的长期工程基线。
- WEB-TASK：定义页面范围、交互与数据状态、端内决策和验收方式。

前端产生新的产品决策、接口变更或跨系统设计时，必须先更新主规格库，再调整 `WEB-TASK`。

## 工单执行规则

- 前端工单使用 `WEB-TASK-###`。
- 一次只执行一个明确工单；超出范围的工作另建工单。
- 已批准 Task/波次的启动或“继续执行”授权规格、权限、Gate 计划和预算内的实现、自测、正式 V/R，以及验证失败后的修复和复验；普通确认统一汇总到任务或波次末，不逐阶段请求批准。
- 执行授权绑定 Task/波次范围和预算；Evidence 与最终验收决定绑定具体 HEAD、计划 hash 和适用截图。候选变化作废旧 PASS、旧 Evidence 绑定和旧验收决定，但不自动撤销范围内的执行授权；新候选重新生成 Evidence 并继续 V/R。
- “改一下”“出效果图”“打开看看”等单独反馈默认只做快速预览和最小定向检查；用户明确只要 feedback 时，不自行启动正式 V/R 或全量回归。不得把反馈以外的任务、新 AC、权限或预算纳入原授权。
- V 未通过时按既有返工/重试预算修复后重跑 V；V PASS 才启动独立 R，R 未通过按分类回 M/V。普通失败及范围内修复只报告进度，不因新 HEAD 要求重新批准；预算耗尽或事实无法核实时保留未通过并汇总，不能伪造 PASS。
- 最终统一提交验收清单，包含最终 HEAD、Gate/V/R、失败与修复、必要截图、风险和待决事项；人工视觉 Review、Heavy/阶段验收及合并、推送、发布仍需明确决定，可在同一清单集中确认，批准前不得执行依赖该决定的动作。
- 只有新增或变更规格范围/权限/已批准 Gate 计划、预算或时限越界、未经批准的破坏性或生产/外部副作用、无法在现有隔离内控制的安全风险、HEAD/权威状态无法对账、用户明确暂停或撤销授权，才在执行中暂停对应范围并请求必要决定；独立任务继续推进。
- 非 Heavy 页面工单只运行对应页面、API 契约和直接依赖的 Playwright/构建 Gate，不得重跑整轮浏览器套件；整轮结束时由最终 Heavy 工单统一运行一次。
- 真实后端路径默认连接工程长期验证数据库，不得为每次页面验证反复创建和删除数据库容器。
- 阶段验收和下一阶段授权可加入最终统一确认清单；必须得到明确决定后才能进入下一阶段。
- 开始时把状态改为 `进行中`，并更新 [`../backend/spec/pending-board.md`](../backend/spec/pending-board.md)。
- 实现必须覆盖核心路径以及适用的加载、空数据、错误、权限、响应式和无障碍状态。
- 完成实现后，在工单“交付记录”中填写变更文件、预览入口、关键决策、检查结果和遗留风险。
- 需要人工或独立验证时，将工单加入 [`../backend/spec/verification-board.md`](../backend/spec/verification-board.md) 并把状态改为 `待验证`。
- 验证通过后，把证据和结论写回工单，状态改为 `已完成`，同步受影响的上游规格并清除看板条目。

## 完成定义

只有同时满足以下条件，工单才算完成：

- 验收标准逐项通过；
- lint、类型检查、相关测试和生产构建结果已记录；
- 指定浏览器、视口和无障碍要求已验证；
- 实际交付差异及遗留风险已记录；
- 必要的上游规格已同步；
- 后端主规格库的两个共享看板中不再保留该工单条目。

## 文档规则

- 工单 ID：`WEB-TASK-###`。
- 文件名格式：`WEB-TASK-###-<kebab-case-name>.md`，模板文件除外。
- 链接使用相对路径或团队可访问的正式规格地址。
- 同一业务规则只保留一个权威定义，不复制后端主规格内容。
- 状态仅使用：`草稿`、`已批准`、`进行中`、`待验证`、`已完成`、`已取消`。
- 禁止删除已经完成的工单；如需纠正，追加变更记录或建立后续工单。
