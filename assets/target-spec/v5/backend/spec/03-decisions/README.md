# 架构决策

本目录保存需要长期追溯背景、取舍和影响的架构决策记录（ADR）。

## 编号与文件名

- ID：`ADR-###`，从 `ADR-001` 开始递增。
- 文件名：`ADR-###-<kebab-case-name>.md`。
- 新建决策时复制 `_template.md`，不得直接修改模板承载正式决策。
- 已接受或已废弃的 ADR 不删除；后续决策通过“取代/被取代”关系保留历史。

## 何时建立 ADR

- 技术选型或架构边界会影响多个 Feature/Design；
- 决策难以回退，或迁移成本较高；
- 存在多个合理方案，需要保留选择依据；
- 对安全、合规、可靠性、成本或团队协作有长期影响。

仅影响单个实现任务的细节写入 Design 或 Task，不单独建立 ADR。
